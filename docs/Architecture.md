# Repository architecture

This document describes how the `fretje.NET.Sdk` repository is organized, how the
packages are built, and which files are generated by tooling.

## Directory layout

```
fretje.NET.Sdk/
├── .github/workflows/ci.yml              # CI: lint config, compute version, pack, test, deploy
├── build.ps1                             # Entry point: generate config → pack all 6 SDKs
├── global.json                           # SDK 10.0.402, test runner = Microsoft.Testing.Platform
├── src/
│   ├── common/                           # Hand-written shared MSBuild
│   │   ├── Common.props                  # Analyzers, properties, NuGet audit, editorconfig globs
│   │   ├── Common.targets                # Package asset restriction, banned packages, analyzer removal
│   │   ├── ContinuousIntegrationBuild.props
│   │   ├── Npm.targets
│   │   └── Tests.targets                 # Disables analyzers during test runs
│   ├── configuration/                    # Analyzer rule definitions
│   │   ├── Analyzer.*.editorconfig       # GENERATED by ConfigFilesGenerator
│   │   ├── Compiler.editorconfig         # GENERATED by ConfigFilesGenerator
│   │   ├── BannedSymbols.NewtonsoftJson.txt  # GENERATED by ConfigFilesGenerator
│   │   ├── BannedSymbols.txt             # Hand-written
│   │   ├── CodingStyle.editorconfig      # Hand-written
│   │   ├── NamingConvention.editorconfig # Hand-written
│   │   └── fretje.NET.Sdk.*.editorconfig # Hand-written per-SDK overrides
│   ├── Sdk/{sdkName}/                    # GENERATED by SdkGenerator
│   │   ├── Sdk.props                     # Imports Common.props + base SDK
│   │   └── Sdk.targets                   # Imports base SDK targets
│   ├── {sdkName}.csproj                  # GENERATED by SdkGenerator — packaging project
│   ├── {sdkName}.nuspec                  # GENERATED by SdkGenerator
│   ├── icon.png / icon.svg
│   └── sources/SharedHttpClient.cs       # Hand-written source injected into consuming projects
├── tools/
│   ├── SdkGenerator/Program.cs           # Generates csproj, nuspec, Sdk.props, Sdk.targets for all 6 SDKs
│   └── ConfigFilesGenerator/Program.cs   # Generates analyzer editorconfigs + banned symbols from NuGet packages
└── tests/fretje.Sdk.Tests/               # Tests verifying SDK behavior
```

The 6 SDK variants are: `fretje.NET.Sdk`, `fretje.NET.Sdk.BlazorWebAssembly`,
`fretje.NET.Sdk.Razor`, `fretje.NET.Sdk.Test`, `fretje.NET.Sdk.Web`, and
`fretje.NET.Sdk.WindowsDesktop`.

## Generated files

Two tools generate files that are committed to the repository.

### `tools/SdkGenerator`

For each of the 6 SDKs, writes:

- `src/{sdkName}.csproj` — packaging project (`NoBuild`, `NuSpecFile`, `NuspecProperties`)
- `src/Sdk/{sdkName}/Sdk.props` — sets `FretjeSdkName`, `CustomBeforeDirectoryBuildProps`,
  `BeforeMicrosoftNETSdkTargets`, imports `Common.props`
- `src/Sdk/{sdkName}/Sdk.targets` — imports the base SDK's `Sdk.targets`
- `src/{sdkName}.nuspec` — the `<files>` block is produced by globbing the `common/`,
  `configuration/`, and `sources/` directories plus the per-SDK `Sdk/{sdkName}/` files,
  icon, license, and README

Run it when you add or remove files under `src/common/`, `src/configuration/`, or
`src/sources/`, or when adding a new SDK variant:

```
dotnet run --project tools/SdkGenerator/SdkGenerator.csproj
```

### `tools/ConfigFilesGenerator`

Generates:

- `src/configuration/Analyzer.<PackageId>.editorconfig` — one per analyzer package
  referenced in `src/` (plus `Microsoft.CodeAnalysis.NetAnalyzers` and
  `Meziantou.Framework.FullPath`, which are hardcoded). It downloads each NuGet
  package, loads the `analyzers/dotnet/cs/*.dll` assemblies into a custom
  `AssemblyLoadContext`, instantiates every `DiagnosticAnalyzer`, and writes one
  `dotnet_diagnostic.<ID>.severity = <level>` line per rule.
- `src/configuration/Compiler.editorconfig` — from the .NET SDK's own
  `Sdks/Microsoft.NET.Sdk/codestyle/cs/*.dll` analyzers.
- `src/configuration/BannedSymbols.NewtonsoftJson.txt` — by reflecting over all
  `N:Newtonsoft.*` types in the Newtonsoft.Json DLL.

The generator preserves hand edits: it re-emits any lines it doesn't understand
(`Unknowns`) and keeps a rule's current severity if the file already sets one.
It prints a `git diff --color` at the end and always exits 0, so the regenerated
files are expected to be committed.

```
dotnet run --project tools/ConfigFilesGenerator/ConfigFilesGenerator.csproj
```

## Build process (`build.ps1`)

```
dotnet run --project tools/ConfigFilesGenerator/ConfigFilesGenerator.csproj
  → regenerates all Analyzer.*.editorconfig, Compiler.editorconfig,
    BannedSymbols.NewtonsoftJson.txt

Get-ChildItem src/*.csproj | ForEach-Object { dotnet pack ... --output artifacts }
  → packs all 6 SDKs sequentially (they share src/obj, so parallel packing
    would race on project.assets.json)
```

## CI (`.github/workflows/ci.yml`)

1. **lint_config** — runs `ConfigFilesGenerator` and fails if `git diff` shows
   changes (generated files must be committed).
2. **compute_version** — scrapes nuget.org for the latest `1.0.X` of
   `fretje.NET.Sdk` and bumps to `1.0.X+1`.
3. **create_nuget** (Windows) — runs `build.ps1 -p:Version=...`, uploads the
   `.nupkg` artifacts.
4. **test** (sharded 1/4 × ubuntu/windows/macos) — runs `fretje.Sdk.Tests`
   against the built packages.
5. **deploy** — pushes to feedz.io and nuget.org (main only), creates a release
   tag. Only publishes when `*.nuspec` or `src/**` changed since the last tag.
6. **final_status_check** — fails the workflow if any job failed.

## How analyzers and rules reach consuming projects

1. `Common.props` adds implicit `PackageReference`s to `Meziantou.Analyzer` and
   `Microsoft.CodeAnalysis.BannedApiAnalyzers` (with `IncludeAssets` including
   `analyzers`).
2. `Common.props` sets `EnableNETAnalyzers=true`, `AnalysisLevel=latest-all`,
   `ReportAnalyzer=true`, and `EnforceCodeStyleInBuild=true` on CI/Release.
3. `Common.props` adds an `EditorConfigFiles` item group that globs
   `../configuration/*.editorconfig` (excluding per-SDK variants), plus the
   per-SDK `$(FretjeSdkName).editorconfig` and the `SingleFileApp` variant when
   applicable. Each rule's severity comes from the generated
   `Analyzer.*.editorconfig` files.
4. `Common.targets` adds `BannedSymbols.txt` and `BannedSymbols.NewtonsoftJson.txt`
   as `<AdditionalFiles>` for the BannedApiAnalyzers, and embeds them in the
   binlog.
5. `Common.targets` restricts NuGet package assets to `runtime;compile` by
   default (so third-party analyzers are not imported), strips analyzers from
   the restricted packages in `RemoveAnalyzersFromRestrictedPackages`, removes
   the SponsorLink and Moq analyzers in `Disable_SponsorLink`, and fails the
   build on banned package references in `FailOnBannedPackageReferences`.
6. `Tests.targets` sets `RunAnalyzers=false` when running tests with
   `OptimizeTestRun` to speed up test builds.

## Adding a new analyzer

1. Add a `PackageReference` in `src/common/Common.props` (or `Common.targets`).
2. Run `ConfigFilesGenerator` to generate `Analyzer.<PackageId>.editorconfig`.
3. Adjust rule severities in the generated editorconfig as needed.
4. Run `SdkGenerator` so the new editorconfig is picked up in the nuspec
   `<files>` block.
5. Commit the generated files.
